# OnniMart

**Вебсистема моніторингу, агрегації та аналізу цін на споживчі товари.** Дипломний проєкт.

OnniMart збирає ціни із сайтів продуктових мереж і **розпізнає один і той самий товар у різних мережах і країнах**. Для будь-якої картки товару система має знати:

- **що це за продукт**: бренд, лінійка, смак чи різновид;
- **які в нього варіації**: смаки та фасування (0,5 л / 1 л / 6 × 0,33 л);
- **скільки коштує кожна варіація** в кожній мережі та кожній країні, разом із ціною за 1 кг або 1 л та історією цін;
- **які є схожі аналоги** інших брендів (у планах);
- **де розташовані магазини** (у планах).

Ядро проєкту і його головна наукова частина — **алгоритм зіставлення товарів** (entity resolution). Він спирається на штрихкоди GTIN, нечітку схожість назв з IDF-вагами, ознаки різновиду (zero, безлактозне, жирність, газованість), блокування кандидатів і модерацію спірних пар.

## Поточний стан

| Компонент | Стан | Пріоритет |
|---|---|---|
| Архітектура та модель даних | працює: лінійка → продукт → фасування → картки мереж → історія цін | **високий** |
| Двигун зіставлення (`packages/matching`) | працює: штрихкод → схожість ≥ 0,90 → модерація 0,70–0,90 → нове фасування → новий товар; precision ≈ 99 % на еталоні зі штрихкодів | **високий** |
| Скрапер (`apps/scraper`, Rust) | 14 мереж: 🇺🇦 Сільпо, NOVUS, Ашан, METRO, ЕКО маркет, МегаМаркет, VARUS; 🇩🇪 ALDI SÜD, ALDI Nord, Globus, Lidl (через Open Prices), а також акції Kaufland, PENNY, NORMA | **високий** |
| Веб (`apps/web`) | робоча заглушка-адмінка для перевірки даних | низький |
| Мобільний застосунок (`apps/mobile`) | шаблон Expo, поза workspaces | відкладено |
| Користувачі, підписки, сповіщення | лише таблиці в схемі | пізніше |

На майбутнє планується охопити відомі й менш відомі мережі Європи, Америки, Японії та Азії; кандидатів зібрано в [docs/04-retail-chains.md](docs/04-retail-chains.md).

## Як це працює

```
сайти мереж ──▶ Rust-скрапер ──▶ Redis «scraper:results» ──▶ воркер: прийом даних ──▶ PostgreSQL
     ▲                                                                │              (картки + історія цін)
     │                                                                ▼
Redis «scraper:tasks» ◀── API / планувальник      воркер: пакетне зіставлення ──▶ канонічний каталог
                              ▲                    (packages/matching)                 │
                              └── Redis «matching:requests» ◀── API ◀── REST /api/v1 ◀──┴── веб-адмінка
```

Система складається з трьох процесів: **API** (HTTP), **воркера** (фонова робота) і **Rust-скрапера**. Вони обмінюються повідомленнями через Redis-списки; формат повідомлень описано в `packages/contracts`.

1. API (кнопка в адмінці) або планувальник у воркері ставить завдання в Redis-список `scraper:tasks`.
2. Rust-скрапер обходить сайт мережі з дотриманням robots.txt, паузою між запитами й чесним User-Agent `OnniMartBot`, а кожен товар кладе в `scraper:results`.
3. Воркер перевіряє повідомлення і зберігає картку мережі (`Listing`), розпізнає фасування й штрихкоди і рахує ціну за одиницю. Новий запис історії ціни (`PriceSnapshot`) з'являється лише тоді, коли ціна змінилась.
4. Після кожного запуску скрапера воркер запускає пакетне зіставлення, яке об'єднує нові картки з каталогом (`ProductLine` → `Product` → `ProductVariant`), а спірні пари відправляє на модерацію.

## Структура репозиторію

| Шлях | Що це |
|---|---|
| `packages/matching` | **двигун зіставлення**: розбір фасування, GTIN, ознаки назв, схожість, рішення, найменування лінійок — чиста бібліотека без БД |
| `packages/contracts` | контракти черг Redis між скрапером, API і воркером, перевірка повідомлень, зразки |
| `apps/api` | NestJS 11 + Prisma 7 (PostgreSQL), два процеси: `src/main.ts` — REST API і модерація; `src/worker.ts` — прийом даних, планувальник, пакетне зіставлення |
| `apps/scraper` | Rust-скрапер: воркер черги `scraper:tasks` і CLI для ручної перевірки |
| `apps/web` | Next.js 16: каталог з порівнянням цін, модерація зіставлень, моніторинг запусків |
| `apps/mobile` | Expo (шаблон, відкладено, поза workspaces) |
| `docs/` | документація до диплома |

## Запуск

Потрібні [Bun](https://bun.sh) 1.3+ і Docker Desktop (на Windows — з WSL 2). Rust локально не обов'язковий: скрапер збирається в Docker.

```bash
bun install
cp .env.example .env                    # задайте REDIS_PASSWORD (і паролі БД)
cp apps/api/.env.example apps/api/.env  # той самий пароль у REDIS_URL, задайте ADMIN_TOKEN
cp apps/web/.env.example apps/web/.env.local  # той самий ADMIN_TOKEN
bun run infra:up        # PostgreSQL, Redis, Meilisearch і Rust-скрапер (воркер)
bun run dev:generate    # Prisma Client
bun run dev:migrate     # міграції
bun run dev:seed        # країни, мережі, категорії
bun run dev:api         # API: http://localhost:3001/api/docs
bun run dev:worker      # воркер: прийом даних від скрапера, планувальник, зіставлення
bun run dev:web         # UI:  http://localhost:3000
```

`dev:api` і `dev:worker` спершу збирають пакети (`bun run build:packages`). Без воркера дані від скрапера накопичуються в Redis, а зіставлення не запускається.

Повідомлення від скрапера не губляться: воркер видаляє їх із Redis лише після запису в БД, а некоректні чи ті, що не вдалося записати за 10 спроб, кладе в `scraper:results:dead`. Повернути їх у чергу:

```bash
docker exec onnimart-redis redis-cli -a "$REDIS_PASSWORD" LLEN scraper:results:dead
docker exec onnimart-redis redis-cli -a "$REDIS_PASSWORD" LMOVE scraper:results:dead scraper:results RIGHT LEFT
```

Після успішного **повного** обходу мережі картки, яких у ньому не було (тижнева акція закінчилась, товар зняли), позначаються `delistedAt` і зникають з каталогу.

Читати дані API може будь-хто, а змінювати (запуск парсингу, модерація) — лише з токеном адміністратора `ADMIN_TOKEN` (`Authorization: Bearer …`; у Swagger — кнопка Authorize). Веб-адмінка додає токен на своєму сервері, у браузер він не потрапляє. API слухає лише `localhost` і приймає запити з браузера лише з адреси вебу (`WEB_ORIGINS`).

У UI на сторінці «Огляд» біля кожної мережі є кнопка «Запустити». Режим «1 стор./категорію» — швидка перевірка за кілька хвилин. Режим «Усе» — повний обхід із паузою 3 с між запитами.

Щоб мережі обходилися автоматично, додайте в `apps/api/.env` рядок `SCRAPE_SCHEDULE=true`. Тоді планувальник у воркері ставитиме повний обхід кожної мережі раз на `SCRAPE_INTERVAL_HOURS` (за замовчуванням 24 год).

## Зіставлення

- **Каталог** (`/products`): товари, що продаються в кількох мережах, з цінами й ціною за кг або л. На сторінці товару — таблиця «фасування × мережі» і перемикач смаків лінійки.
- **Зіставлення** (`/matching`): статистика і черга модерації. Спірні пари (схожість 70–90 %) підтверджує або відхиляє людина.

```bash
bun run match:evaluate                        # precision / recall / F1 для порогів (еталон — штрихкоди)
cd apps/api && bun run listings:reparse      # перерахувати фасування з rawData
cd apps/api && bun run catalog:reset --yes   # видалити каталог (потім «Зіставити зараз»)
```

## Скрапер без API

```bash
bun run scraper:cli silpo --max-pages 1 --category napoi
```

## Тести

```bash
bun run test            # пакети (matching, contracts) і API (bun test)
bun run test:matching   # лише двигун зіставлення
bun run typecheck       # збирає пакети й перевіряє типи
bun run scraper:test    # Rust-скрапер (cargo test у Docker)
```

Після змін в API-контрактах оновіть клієнт для web: `bun run dev:openapi && bun run dev:orval`.

> Якщо локальна БД уже має стару міграцію `20260829154028_init_schema`, Prisma запропонує скинути базу. Скиньте її командою `cd apps/api && bun x prisma migrate reset` (локальні дані буде видалено).

## Принципи збору даних

Скрапер чесно представляється ботом і дотримується robots.txt та `Crawl-delay`. Він не обходить Cloudflare, captcha чи авторизацію: отримавши 403, зупиняється. Зберігаються лише факти (назва, ціна, фасування, штрихкод) і посилання на зображення. Деталі та правові рамки описано в [docs/01-data-sources.md](docs/01-data-sources.md).
