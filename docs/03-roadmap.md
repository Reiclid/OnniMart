# План робіт

Тема: **вебсистема моніторингу, агрегації та аналізу цін на споживчі товари «OnniMart»**.

Ядро системи — **зіставлення одного й того самого товару з різних мереж в один запис** (див. [02-database.md](02-database.md#зіставлення-товарів-головна-наукова-частина)). Усе інше — збір, підписки, сканер, аналітика — будується навколо нього.

Терміни нижче орієнтовні, з розрахунку на захист у червні 2027.

**Пріоритети (з 18.10.2026):** 1) архітектура, 2) двигун зіставлення, 3) скрапер. Веб — робоча заглушка-адмінка, мобільний застосунок відкладено. На майбутнє — мережі з усієї Європи, Америки, Японії та Азії ([04-retail-chains.md](04-retail-chains.md)).

## Етап 2а. Архітектура — 🟡 у роботі (жовтень–листопад 2026)

Зроблено:

- [x] Двигун зіставлення винесено в бібліотеку `packages/matching` (нормалізація, ознаки назв, схожість, індекс, найменування) — без залежностей від БД і фреймворку, з власними тестами.
- [x] Контракти черг Redis — `packages/contracts`: назви черг, типи повідомлень, перевірка повідомлень з `scraper:results` і зразки (`fixtures/`).
- [x] Окремий фоновий процес `apps/api/src/worker.ts`: прийом даних, планувальник і пакетне зіставлення не ділять event loop з HTTP. API просить зіставлення через `matching:requests` і читає стан з `matching:state`.
- [x] Порожній `packages/shared` прибрано, `apps/mobile` виведено з workspaces.

Далі (за результатами технічного аудиту):

- [x] Надійна черга результатів: `BLMOVE` у `scraper:results:processing`, повтор з паузою до 60 с, `scraper:results:dead` для некоректних повідомлень і після 10 спроб.
- [x] Завдання скрапера в `scraper:tasks:processing`, heartbeat `scraper:heartbeat`, втрачені запуски → `FAILED`; мережу не можна поставити в чергу двічі; пауза між запитами ≥ 3 с.
- [x] Застарілі картки: після успішного повного обходу картки, яких у ньому не було, отримують `delistedAt` і зникають з каталогу (захист: обхід мав побачити ≥ 50 % активних карток).
- [x] Закінчення акцій за датою: `Listing.promoEndsAt`; воркер кожні 10 хв повертає картку до звичайної ціни й пише запис історії (на локальних даних знято 1 335 прострочених акцій з 2 937).
- [x] Зіставлення: рішення пишеться лише в незіставлену картку, помилка картки не зупиняє пакет, модератор не може прийняти застарілого кандидата; назви без бренду й значущих слів не зливаються автоматично.
- [x] Інкрементальне зіставлення: ключі пошуку в `match_keys`, пакет читає лише нові картки й кандидатів зі спільними ключами; рішення збігаються з повним режимом (100 %).
- [x] Частоти слів (IDF) у PostgreSQL: `listings.nameTokens`, воркер не завантажує всі назви карток.
- [x] Реєстр мереж у БД: ~400 мереж із 63 країн зі статусами й примітками; валюта — будь-який код ISO 4217.
- [ ] Модель для глобального охоплення: курси валют, ціни магазинів/регіонів, геодані магазинів (OpenStreetMap), аналоги товарів.
- [ ] Rust-сторона контрактів: тест, що парсер генерує повідомлення, які приймає `packages/contracts`.

## Відомий технічний борг

- Скрипт `test` у `apps/api` запускає `bun test`, бо Jest 30 не працює в рантаймі Bun. Spec-файли сумісні з обома.
- Мобільний застосунок — шаблон Expo поза workspaces (його `package.json` ще посилається на видалений `@repo/shared`).
- Meilisearch піднімається в docker-compose, але не використовується: або реалізувати пошуковий індекс, або прибрати.
- Умови користування АТБ, Сільпо та zakaz.ua треба перечитати вручну (див. [01-data-sources.md](01-data-sources.md#юридичні-рамки)).
